# TurboBaby — контекст для Claude Code

## Что это
Splinter — Telegram-бот учёта для аренды мотобайков (TurboBaby, Пхукет, владелец Филипп, 38 байков). Работает на этом сервере 24/7 как systemd-сервис `splinter`.

## Главные правила работы с этим проектом
- Режим автономии/стопов/логирования — см. раздел «РЕЖИМ РАБОТЫ» ниже (он главный).
  Кратко: локальные правки кода и диагностику делаю сам; стоп и «да» — только перед
  необратимым (деплой/push/restart/запись в рабочие таблицы/SQL/удаление). Дифф показываю
  в ревью (KB_review) перед деплоем, а не на каждую локальную правку.
- НИКОГДА не коммить и не пушить секреты: .env, memory.db, *.session. Они в .gitignore.
- После правки кода: предложи закоммитить в git, и напомни перезапустить сервис: `systemctl restart splinter`.
- Логи бота: /root/turbobaby-manager-bot/splinter.log
- Проверить статус: `systemctl status splinter`

## Бизнес-правила (НЕ нарушать в коде)
- Никаких массовых рассылок клиентам.
- Изменения в Google Sheets — только через approve-флоу.
- HONDA CLICK 125 не сдаём.
- Депозит = либо деньги, либо паспорт (не оба).
- Доставка только по Пхукету.
- Тайская команда (Пым) с клиентами не общается.

## Архитектура
- bot.py — точка входа, роутер, планировщики.
- splinter.py — супервайзер групп, vision.
- claude_client.py — «мозг», эскалация, инструменты.
- bridge_client.py — HTTP-клиент к Apps Script Bridge (Google Sheets).
- auditor.py — надзор (факты + язык RU/TH).
- memory.py — SQLite memory.db (правила/история).
- prompts.py — системные промпты.
- devbot.py — дев-бот в теме 328 (внутри процесса bot.py, не отдельный сервис); см. раздел «ДЕВ-КОНТУР O4».
- orchestrator_daemon.py — демон исполнения Bridge-очереди через headless `claude -p`
  (отдельный systemd-сервис `orchestrator-daemon`; splinter от него не зависит).

**Адаптация плана (мета-дирижёр кусок 2, 07.07.2026):** при `PLAN_ADAPT=1` в .env (отдельный флаг,
независимый откат `PLAN_ADAPT=0`+рестарт демона) после КАЖДОГО done-шага декомпозера думатель (та же

исключение) = keep, не хуже прежнего. Красное НЕ ослаблено; слои живут вместе: провал шага →
самопочинка, done шага → адаптация (после 🩹-done адаптация не зовётся — реборн того же номера ждёт).

- Гейт по ячейке = отдельная парсер-функция (`bookingParseOdo_`, `bookingParseDate_`):
  принимает РОВНО задокументированные живые форматы, всё прочее → null → fail-closed err.
  Недопарс запрещён: лучше null (ручное закрытие), чем «12» из «12 345 Km» (гейт-пустышка).
- Колонку в харнессе покрывать ПАРОЙ: живой формат → гейт работает по существу;
  неформат/пусто/голая дата → fail-closed err. Только идеализированный мок = тест зелёный,
  прод стоит.

### ПРАВИЛА ДИСЦИПЛИНЫ ИСПОЛНЕНИЯ (заведено 16.07.2026 ревизией)

**Одно событие = один DONE — пишет исполнитель, куратор/Termux ссылаются:**
После каждого завершённого действия строку DONE пишет ТОТ, кто его выполнял (headless-задача, Termux-сессия, Cowork). Куратор/штаб/Termux ссылается на эту строку ключом (дата/тема), а не дублирует. Дублирование DONE от разных исполнителей за одно действие = ложная история (мозг противоречит сам себе).

**Декомпозируй только если >45 мин или несколько систем — иначе одиночное «тз:»:**
Критерий декомпозиции — ОБЪЁМ, не желание структурировать. Если задача одна система и укладывается в один Claude-сеанс (~45 мин) — одиночное «тз:». Декомпозируй только если: (1) одновременно несколько сервисов/репо, (2) очевидно >45 мин. Избыточный декомпозер добавляет шаги-синтетики, задержки и риск halt-on-fail на промежуточных.

**Один инцидент = один фикс-коммит + один инвариант-детектор (не цепь задач):**
Инцидент (неожиданное поведение живой системы) → один headless-заход: диагноз + фикс + тест-инвариант (обнаружил бы инцидент заранее?) + коммит. Не плодить цепочку декомпозера из 5+ шагов на разбор инцидента — это раздувает очередь и прячет суть. Инвариант-детектор = живая страховка (добавляем в registry_check.py / тест-файл).

## ГИГИЕНА cc_log (заведено 25.06.2026)

cc_log РАСПУХАЕТ → штаб на каждом «проверь» читает огромный док, переполняет память, у Филиппа
запускается авто-сжатие диалога. Чинить по КОНКРЕТНОМУ ТРИГГЕРУ (не размыто «регулярно»):
- **🔴 ЖЁСТКИЙ ТРИГГЕР (заведено 29.06): подрезка cc_log = ОБЯЗАТЕЛЬНЫЙ ШАГ В КОНЦЕ КАЖДОЙ СЕССИИ**,
  как бэкап — НЕ ждать 40 КБ, НЕ ждать, что «кто-то инициирует». Закончил работу сессии → ПЕРЕД финальным
  отчётом перенести записи старше ТЕКУЩИХ суток в архив, в рабочем cc_log оставить ТОЛЬКО сегодняшнее + шапку.
  Пассивное правило «подрезать >40 КБ» неделями не срабатывало (никто не инициировал, док пух до ~80–128 КБ) —
  поэтому теперь это часть рутины завершения, не отдельное решение.
- **ДОП.ТРИГГЕРЫ (страховка):** cc_log превышает ~40 КБ ИЛИ ревизия (KB_MASTER §6, чек-лист п.6) — подрезать
  немедленно, не дожидаясь конца сессии. Перенос: ВСЁ старше ПОСЛЕДНИХ суток в архив `KB_claude_code_log_archive`
  (`name=cc_log_archive` — ТОЛЬКО по name, id менялся 02.07.2026 при миграции Doc→plain, сырой id не хардкодить).
  В рабочем cc_log — только сегодняшнее + шапка.
- Перенос: read_doc архив → старые записи cc_log ПРЕПЕНДнуть (старое сверху) → write_doc(id=архив);
  затем подрезать cc_log. **АРХИВ ПИШЕТСЯ ПЕРВЫМ + сверка образца, ТОЛЬКО потом подрезка cc_log** —
  чтобы при сбое ничего не потерять. Бэкап-снимок cc_log на диск (/tmp) перед правкой.
- **ВРЕЗКУ СВЕРХУ СОХРАНЯТЬ.** При любой записи в cc_log врезку (старт-блок ⛔) матчить по ═-only-строке
  (строка целиком из ═), а НЕ по фикс-длине константы — иначе splice теряет шапку (так и случилось 25.06).
  Новые записи кладутся ПОД врезкой (после её закрывающей ═-линии), врезка остаётся первой.
- Зона 🟢 (cc_log + архив — Brain-доки, не git docs/*, синк не нужен).

Встроенный детектор инъекций форсит подтверждение на некоторых формах команд, даже если они в allowlist. Это НЕ отключается конфигом (--dangerously-skip-permissions снял бы и гейт боевой записи — ЗАПРЕЩЕНО). Поэтому пишем команды в форме, которая guard не триггерит:

   venv/bin/python3 /root/turbobaby-manager-bot/_recon.py
3. GIT в другом репозитории: git -C <dir> ..., НЕ cd <dir> ; git ...
4. ОДНА ПРОВЕРКА = ОДНА КОМАНДА В ОДНУ СТРОКУ. В проверочных командах НЕ использовать:
   `2>&1`, `2>/dev/null`, `>`/`>>` (редиректы), `||`, `&&`, `;`-цепочки, `$(…)`/`` `…` `` (подстановку
   команд), heredoc. Любая из этих форм триггерит встроенный guard → лишний переспрос.
   Нужен вывод — смотреть напрямую (`cat`/`grep` по абсолютному пути); нужен exit-код — отдельной строкой
   (`echo $?` без подстановки внутри другой команды). Несколько действий — несколько отдельных вызовов.
   ПЛОХО:  echo "ошибок: $(grep -c ERR log)"   ·   cmd1 && cmd2 ; cmd3 > out
   ХОРОШО: grep -c ERR /abs/log   (затем отдельной строкой следующая проверка)

Цель: технические читающие команды идут БЕЗ подтверждения. Гейт боевой записи (sqlite3 memory.db, clasp, confirmed=true в Лист1/CRM) — ОСТАЁТСЯ как есть, его НЕ обходим.

⚠️ ВАЖНО: запись в allowlist (`.claude/settings.local.json`) встроенный guard НЕ отключает — guard на ФОРМУ
команды отдельный механизм. Доказательство: в старом allow висели echo-`$(…)`-записи, но guard всё равно
переспрашивал. Поэтому переспросы на форме лечатся ТОЛЬКО чистой формой команды (пункты 1–4), а не allowlist.
Allowlist решает другое — КАКИЕ инструменты/команды разрешены без «да» (зелёная зона) vs под ask-гейтом
(красная/прод: sqlite3, clasp push/redeploy/deploy/run, git push, systemctl restart/stop).

## РАБОТА С ТЕЛЕФОНА (tmux) — заведено 17.06.2026

Чтобы Claude Code НЕ обрывался при потере связи в Termius (телефон уснул, метро, переключение сети),
работаем внутри постоянной tmux-сессии `cc`. Процесс живёт на сервере, даже если телефон отвалился.

**Рабочий цикл (простыми словами):**
- **Запустить сессию (первый раз):** `tmux new -s cc`
- **Внутри сессии — запустить Claude Code:** `cd /root/turbobaby-manager-bot && claude`
- **Отцепиться, НЕ закрывая работу** (после этого Termius можно гасить, телефон в карман): нажать `Ctrl+B`, отпустить, затем `D`
- **Вернуться (после обрыва или позже):** `tmux attach -t cc` — увидишь ровно то, что было, работа не прервалась
- **Список сессий:** `tmux ls`

**Автозапуск (настроено):** при SSH-входе сессия `cc` подцепляется сама (а если её нет — создаётся) —
строки в `/root/.bashrc` (срабатывает только для интерактивного SSH, не мешает скриптам). То есть обычно
достаточно просто зайти с телефона — попадёшь сразу в `cc`. Если случайно отцепился — `tmux attach -t cc`.

**Шпаргалка по Ctrl+B (префикс tmux):** `Ctrl+B` затем `D` — отцепиться; `Ctrl+B` затем `[` — режим
прокрутки (выход — `q`); `Ctrl+B` затем `C` — новое окно. Главное — `D` (detach) и `tmux attach -t cc`.

## НАБЛЮДАЕМОСТЬ TERMUX — `cclog` (заведено 05.07.2026)

Живой Claude Code в Termux сам в `cc_log` НЕ пишет → штаб (Claude-на-сайте) видит только Drive-журналы,

- **Вызов из репо:** `venv/bin/python3 cclog.py "<текст итога>"` → `DONE <UTC> UTC (Termux): <текст>`.

## Правила рабочей среды — свод (заведён 25.07.2026)

Полный разбор с фактами: [`docs/ENV_PLAYBOOK.md`](docs/ENV_PLAYBOOK.md). Файл одинаков в ОБОИХ
репозиториях. Здесь — только сами правила; за каждым стоит живой инцидент 23–25.07.

1. **Каналы.** Артефакт файлом в `docs/artifacts/` → строка `ARTIFACT` в журнал → FACT-отчёт в
   сессии → строка `DONE`/`ASK`. Финальный `DONE` **ссылается на артефакт путём**, а не
   пересказывает его. Запись в Brain-доки с ПК — только через `brain_writer`.
2. **Мощность — три РАЗНЫЕ ручки:** модель, усилие (`--effort`), бюджет мышления. **Замер 24.07:
   ключевое слово в тексте задания уровень усилий НЕ меняет** — это конфигурационная ручка
   (`ultrathink` стоял в 10 заданиях из 11, признаком тяжести быть не может). Имя модели обязано
   быть ПОЛНЫМ: короткий алиас даёт `404`. Клиент (RC/Desktop) перекрывает `effortLevel` репо.
3. **Одна задача — один вызов.** Серверный заход не дробить: бэкап → правка → тесты → гейт →
   коммит → откат при любом красном, всё внутри одного ssh. 25.07 это спасло дерево: вызов упёрся
   в 4 красных теста и **сам откатился**. Вывод гейта **никогда** не захватывать в `$( )`.
4. **Очередь внутри сессии последовательна.** Связанные задачи — по очереди здесь же, они
   переиспользуют собранную фактуру. Новая сессия — только под несвязанную тему.
5. **Судить по ДЕЙСТВИЮ, а не по подстроке.** Нет числа или имени (PID, путь, таблица, хост) —
   карточки быть не должно. Слова `гейт`/`тесты`/`коммит` в признаках не держим. Разбор сегментов
   обязан уважать кавычки. Явный запрет владельца бьёт всё остальное.
6. **Финальный шаг сессии — итог в журнал** (`DONE`/`ASK`). Без записи сессия незавершена. Боевые
   токены в тексте записи **называть словами**, а не цитировать: поверх нашего гарда работает
   второй, внешний слой защиты, которого в репозитории нет.
7. **Сводка — гипотеза, числа — факт.** Сверять с сырым выводом; при расхождении верить числам и
   говорить об этом. За три дня сводка ошибалась четыре раза, числа — ни разу.
8. **Проверка повторяет живой формат запуска.** Фикстура снимается с прода; мок, переставший
   задевать ветку, хуже отсутствующего; способ запуска (`-m unittest` против прямого файла) — тоже
   часть формата; голдены детекта — на дословных фразах.
9. **Класс-фикс — сразу на ОБЕ полосы.** Иначе зеркальные дыры: 25.07 признак «это тест-прогон» на
   VPS смотрел имя файла, а на ПК окружение — один класс, две течи. Не закрыть вторую сейчас —
   записать её в остатки **с точками касания**.
