## 💰 ЛОГИКА ЦЕН

### Шаг 1: Глобальная скидка по категории
В `'Календарь бронирования'!H3/I3/J3`:
- H3 — для Мотоциклы 1 (текущее: 15%)
- I3 — для Мотоциклы 2 (15%)
- J3 — для Скутеры (25%)

`цена_с_глобальной_скидкой = базовая_цена * (1 - глобальная_скидка_категории)`

### Шаг 2: Скидка за срок аренды

**Мотоциклы 1 (XSR, CB300, REBEL, MT-03, NINJA400):**
- 1-5 дней → 0%
- 6-13 дней → 5% + 1% за каждый день сверх 6 (макс ~12% на 13 дней)
- 14-30 дней → 25% + 1.5%/день сверх 13 (макс 45%)
- 30+ дней → 45%

**Мотоциклы 2 (VULCAN, CBR650, CB650, XSR900, R7):**
- 1-5 дней → 0%
- 6 дней → 10%
- 7-13 дней → 11% + 1%/день
- 14-30 дней → 18% + 2%/день
- 30+ дней → 50%

**Скутеры:**
- 1-5 дней → 0%
- 6 дней → 5%
- 7-13 дней → 6% + 1%/день
- 14-30 дней → 18% + 1.0625%/день
- 30+ дней → 35%

### Шаг 3: Депозит — два варианта на выбор

⚠️ **Только ОДНО из двух — либо деньги, либо паспорт. БЕЗ всяких +1500/день.**

1. **Денежный депозит** — стандартный (2,000-25,000 ฿ в зависимости от байка)
2. **Депозит-паспорт** — клиент оставляет паспорт вместо денег

**Правила использования депозит-паспорта:**
- **Скутеры с депозитом до 5,000 ฿** (PCX, NMAX, ADV 150/160) → паспорт **редко предлагаем**, обычно требуем деньги
- **Байки с депозитом 7,000 ฿** (XSR 155, XMAX, ADV 350) → **можно предложить паспорт**
- **Байки с депозитом от 15,000 ฿** (CB 300R, MT-03, NINJA 400, CBR 650R, CB 650R, VULCAN, XSR 900, R7, XADV 750) → **АКТИВНО ПРЕДЛАГАТЬ паспорт** — это удобнее клиенту чем большой кэш-залог

⚠️ Цена аренды от выбора депозита **НЕ зависит**. Тариф одинаковый.

**Депозит в валюте (USD / EUR) — уточнено 07.06.2026:**
- Денежный депозит можно принимать в долларах/евро. Сумму берём по модели из таблицы
  «Календарь бронирования» (в батах) → переводим в примерный эквивалент USD/EUR → **округляем до сотен**.
- Возврат — **тем же способом** и в той же зафиксированной сумме (пример из диалогов:
  «200 USDT — так зафиксировали, так и вернём»).
- Правило «депозит = деньги ИЛИ паспорт (не оба)» при этом НЕ меняется.

## ✅ ПРОЦЕСС ЗАКРЫТИЯ АРЕНДЫ (КРИТИЧНО!)

⚠️ **Никогда не нажимать "Завершена" просто потому что прошла дата возврата!**

Перед тем как переключить статус аренды на "Завершена" — бот ОБЯЗАН проверить **6 условий**. Если хотя бы **одно** не выполнено — **НЕ закрывать**, эскалировать Филиппу с конкретным вопросом что не так.

### Чек-лист закрытия аренды:

#### 1. ✅ Долги по аренде = 0
- Колонка **I** ("Долг") в листе "клиенты" должна быть пустая или 0
- Колонка **J** ("К оплате на данный момент") должна быть полностью покрыта **K** ("Оплачено")
- Если есть долг — **не закрывать**, сначала клиент должен доплатить или Филипп должен принять решение списать

#### 2. ✅ Байк физически возвращён (подтверждение в переписке с клиентом)
- В TG/WhatsApp переписке с клиентом должно быть **явное подтверждение** что байк передан обратно ("вернул", "отдал", "Pleum забрал", "встретились в офисе" и т.п.)
- Время возврата зафиксировано в чате
- Если переписки нет / клиент не отвечает — **НЕ закрывать**

#### 3. ✅ Фотоотчёт принятия байка
- Тайские помощники (сейчас — Pleum) при приёме байка делают **фотоотчёт**: состояние корпуса, пробег, бензин, шлемы, ключ/брелок
- Эти фото должны существовать (где-то в Google Drive / TG / WA)
- Если фотоотчёта нет — байк формально **не принят**

#### 4. ✅ Претензий от тайцев нет
- После приёма Pleum (или кто принимал) подтвердил: "всё ок, без повреждений, всё на месте"
- Если есть повреждения / царапины / разбит фонарь / разбит руль / потеряны ключи — это **отдельный процесс** (вычеты из депозита, согласование с клиентом)
- Только после **окончательного "всё ок"** можно идти дальше

#### 5. ✅ Депозит обработан
- **Если деньги:** возвращены клиенту (или вычеты согласованы)
- **Если паспорт:** возвращён клиенту лично в руки
- Никаких "Депозит вернём завтра" — пока не обработан, аренда **не закрыта**

#### 6. ✅ Все доплаты/вычеты учтены
- Просрочка → 30% надбавка посчитана (по правилу 3 договора)
- Грязный байк → 200 ฿ вычет
- Неполный бак → 80/100 ฿ за деление
- Потеря ключа/брелка → 500/3000-5000 ฿
- ТО просрочено → штраф учтён
- Всё что должно быть **внесено в систему** ДО закрытия

- Факт: XMAX 4724 — ТО Oil=14900, интервал 4000 → следующая 18900, текущий 19705 → ПРОСРОЧЕНО ~805 км.

### Надзор за важным (live-обкатка, 31 мая 2026)
- Splinter сам замечает ВАЖНОЕ в опергруппах (ДТП/авария, серьёзный ремонт, просрочка ТО, потеря ключа, течь, тормоза, «не заводится»).
- **Не крепит сразу** — сначала спрашивает в группе «это важно, закрепить и напоминать? @Pleummmm подтверди». Крепит ⚠️-сообщение (двуязычное) ТОЛЬКО после подтверждения Пыма/владельца.
- **Напоминание раз в 3 дня** автоматически (планировщик в 10:00 проверяет, повторяет закреп тем пунктам, где прошло ≥3 дней).
- **Закрытие через подтверждение:** Splinter ловит «сделано/заменили/починили/готово» (от любого сотрудника) → спрашивает «решено, открепить? @Pleummmm подтверди» → после подтверждения переводит open→done и снимает закреп.
- Хранилище: лист `важное` в Bot Data. Инструменты мозга: `flag_important`, `close_important` (оба только после подтверждения).

### Аудитор — надзор за ботом (live-обкатка, 1 июня 2026)
Второй логический слой (модуль `auditor.py`), который НЕ доверяет Splinter и сверяет его работу с ФАКТАМИ (Bot Data, Лист1, memory.db) и правилами KB. Гибрид: детерминированные проверки + LLM на сложное.
- **Что ловит:** галлюцинации («сказал записал правило» → в memory.db нет), ложные рапорты («закрепил важное» → в листе нет/без msg_id), ошибки логики (ТО интервал 6000 вместо 4000/5000), запись пробега с фото без подтверждения.
- **Качество общения:** смешение языков (кириллица в тайском блоке и наоборот), неполная двуязычная структура (нет одного из блоков), эмодзи вместо слов (паспорт/деньги). Детектируется по диапазонам символов Unicode, без LLM. Глубокие странности перевода (смысл/транслит/тон) — опц. через LLM в отчёте.
- **Принцип:** сверяет требование→результат на основе реальных вводных (запрос + данные + правила), а не «второе мнение модели». Вердикты считаются детерминированно, LLM — только для резюме.
- **Журнал:** лист `аудит` в Bot Data (запрос, инструмент, аргументы, заявленный результат, вердикт, severity, предложение правки, статус).
- **Действия при находке:** только флаги + предложения правок. Сам НЕ правит память/правила — применяется после апрува Филиппа.
- **Отчёт:** раз в сутки в HQ (09:30) + по команде `/audit` (за 7 дней). Каждое действие бота проверяется сразу после выполнения (realtime-лог в журнал), сводка — раз в день.

### Диалог с владельцем = приоритет
- Филипп может в любом чате дать новую вводную/правку — Splinter принимает её (через `remember_rule` — как правило, или `save_note` — как заметку) и подтверждает.
- Правила глобальные (применяются во всех чатах через мозг).
- **Контекст ДАННЫХ — узко по теме группы** (каждая группа = своя тема: касса/обслуживание/доставка/отметка). Глобальные бизнес-данные и финансы Филипп получает ТОЛЬКО в Turbo HQ. В денежной группе «баланс» = наличные кошелька (`get_wallet_balance`), НЕ финансы бизнеса (`get_finance`).
- **Обучение — всегда:** узкий контекст данных НЕ мешает учиться. Новое правило/вводную можно дать в любой группе по любой теме — Splinter всегда принимает и запоминает.

### Архитектура (два процесса, один мозг)
- **Юзербот @turbophuket** (Telethon) и/или **официальный бот** — слушают группы.
- Решение: Splinter = **официальный бот** (явный, безопасный, как @Turbobabyre раньше), добавлен в группы как админ с Privacy Mode OFF.
- Все данные → **Bridge POST** → таблица **Bot Data на Drive Филиппа** (переживает перезапуски, видно глазами).
- Память правил/заметок: SQLite `memory.db` (быстрый кэш) + дублирование важного в Drive.
