# Квитанция ТО говорит одно и то же на обоих языках (14.08.2026)

## 1. Класс

У квитанции факта ТО две половины — тайская и русская, — и складывались они РАЗНЫМИ выражениями
над ОДНИМ исходом записи. Дверь кнопки «да» (`splinter.py`, ветка `action == "done"`):

```python
rep_ru = (f"✅ Записано: {_sp_labels_ru(written)} на {odo} км" if written else "⚠️ ничего не записано")
if failed:
    rep_ru += f" · не прошло: {', '.join(k for k, _ in failed)}"
await _send_retry(context, ...,
                  text=(f"🐀 Splinter · 📌 {bike}\n"
                        f"🇹🇭 ✅ บันทึกแล้ว: {_sp_labels_th(written)} ที่ {odo} กม.\n"   # ← безусловно
                        f"{_SEP}\n"
                        f"🇷🇺 {rep_ru}"))                                             # ← с отрицанием
```

Русская половина знала отказ (тернарник), тайская — нет (шаблон без ветки). Пока запись
проходила, обе говорили одно; на отказе они расходились **в одном сообщении**: механик читал
успех, владелец — отказ.

Вторая дверь (доверенный ответил ЧИСЛОМ вместо кнопки, `handle_service_result`, статус
`ждёт_подтверждения`) была хуже: там **безусловны обе** половины, а отказ дописывался хвостом
только по-русски — тайская молчала о нём вовсе.

## 2. Живой случай (13.08, splinter.log)

```
05:19:07  ТО фаза2 запись по «да» @Pleummmm: written=[] failed=[('abs','receipt_unknown')] odo=37015
05:21:41  ТО фаза2 запись по «да» @Pleummmm: written=[] failed=[('abs','receipt_unknown')] odo=20747
```

Байки NMAX 155 GREEN-B 4957 и X MAX 300 NEW BLUE 4724 (12:19 и 12:21 по Пхукету). Прогон
дословных формул дерева `a4489a5` через `git worktree` даёт ровно ту строку, что видели люди:

```
🇹🇭 ✅ บันทึกแล้ว: — ที่ 37015 กม.            → исход «записано»
🇷🇺 ⚠️ ничего не записано · не прошло: abs   → исход «не записано»
```

Пустое тире вместо названия работы — то же незнание, только молча: `_sp_labels_th([])` отдаёт «—».

Обе величины в Лист1 на самом деле **легли** (перечитывание живым мостом 13.08, `write_fact`,
коммит `c3e5543`), то есть тайская половина случайно оказалась ближе к правде. Оправданием это
не является: она говорила «записано» не потому, что знала, а потому, что не умела иначе.

## 3. Замер

Реплей **живым классификатором** по splinter.log (окно `2026-06-01 19:53:24 … 2026-08-14

корпусе):

| | число |
|---|---|
| квитанций факта ТО | **12** (дверь кнопки 12, дверь числа 0) |

## 4. Решение

`service_receipt.py` — чистая функция «исход записи → две половины». Обе половины рендерит ОДНА
функция из ОДНОГО вердикта (`verdict`), собрать их порознь у вызывающего нет способа: `receipt()`
отдаёт `th` и `ru` вместе с исходом.

**Три исхода, а не два** (тот же замок против ложного зелёного, что у `write_fact`, `card_deadline`
и О3):

| исход | когда | 🇹🇭 | 🇷🇺 |
|---|---|---|---|
| ЗАПИСАНО | принята хоть одна позиция | `✅ บันทึกแล้ว: …` | `✅ Записано: …` |
| НЕ ЗАПИСАНО | не принято ничего, КАЖДЫЙ отказ вынес сам мост | `❌ บันทึกไม่สำเร็จ: …` | `❌ Не записано: …` |
| НЕИЗВЕСТНО | не принято ничего, хоть один отказ — молчание транспорта | `⚠️ ไม่ทราบผลการบันทึก: …` | `⚠️ Исход записи НЕИЗВЕСТЕН: …` |

Ветка «неизвестно» прямо просит не жать кнопку снова (`— ต้องตรวจสอบในตารางก่อน อย่าเพิ่งกดซ้ำ` /
`— проверь Лист1, вслепую не повторять`): расписка не пришла ≠ запись не легла (13.08 легли обе),
а повтор вслепую положил бы ВТОРУЮ строку.

**Направление сомнения — в «неизвестно».** Незнакомый код отказа, пустая строка ошибки, исключение
на нашей стороне не дают права утверждать «не записано»: утверждение о мире требует факта о мире.
Вокабуляр определённых отказов берётся ГОТОВЫМ у `write_fact.SETTLED_ERRORS` (мост вынес их сам,
проверив номер, подтверждение, убывание пробега); своё в нём одно — `bad_odometer` (цикл записи не
начинался, писать было нечего). Хвост `«код/исход»`, который руки клеят после перечитывания
(`_sp_write_done`: `f"{error}/{fact.state}"`), решает первым: `absent` — выяснено, `unknown` — нет.

**Имя работы либо стоит, либо названо неопределённым.** Пустого тире в квитанции больше нет:
список либо назван ярлыками, либо сказано «работа не названа» / «ไม่ได้ระบุงาน»; вид, которого нет
в словаре ярлыков, печатается ключом (имя без перевода лучше тире); неназванный пробег тоже
называется («пробег не назван» / «ไม่ได้ระบุเลขไมล์»), а не проглатывается.

**Частичный отказ виден обеими половинами** — хвосты `· ไม่ผ่าน:` / `· не прошло:` и
`· ไม่ทราบผล:` / `· исход неизвестен:`; в русском хвосте теперь стоит ЯРЛЫК работы, а не ключ
вида (`abs` → «масло ABS»).

## 5. Границы

* **Здоровый путь БАЙТ-В-БАЙТ прежний** — доказано голденом на пяти живых успешных квитанциях
  корпуса: строка сравнивается с прежней формулой, собранной живыми `_sp_labels_th/ru`.
* Запись не тронута ни на строку: `_sp_write_done`, гейт доверенного, `confirmed=True`, дедуп и
  синк зеркала прежние (проверяется вызовами моста в тесте). Правка меняет СЛОВА, а не запись.
* `_sp_labels_ru/th` не изменены — их читают ещё 8 мест (заявка, переспрос, эскалация); правило
  «одна цель» соблюдено, лечится квитанция.
* В рабочие таблицы этим заходом не писалось ничего; пропущенные строки зеркала 4957/37015 и
  4724/20747 НЕ досылались — отдельное решение владельца.
* Граница устройством: у `service_receipt` импорт ровно один (`write_fact`), ни сети, ни файлов,
  ни времени — инвариант `SERVICE_RECEIPT_PURE` (ast, в гейте).

## 6. Тесты

`tests/test_service_receipt.py` — **24 проверки**: голдены на дословных 37015/20747; замок в обе
стороны (успех → успех обеими, отказ → отказ обеими, исход каждой половины вычитывается из НЕЁ
САМОЙ головным маркером и сверяется с другой); «в строке ровно один маркер исхода»; три исхода;
имя работы; здоровый путь байт-в-байт; сквозное на живом коде splinter через ОБЕ двери (кнопка
«да» и ответ числом) с дословным отказом расписки; чистота (ast).

Прогон «ДО правки» — на дереве `a4489a5` через `git worktree` ТЕМ ЖЕ файлом: **сьют не стартует
вовсе** (`ModuleNotFoundError: service_receipt` — у того дерева нет ни модуля, ни самого понятия
единой квитанции), поэтому «до» измерено отдельной пробой дословных формул того дерева
(`_scratch_receipt_0814/probe_before.py`): **половин разошлось 2 из 4**, после правки — **0 из 4**.
Тест сам защищается от ловушки метода: корень берётся от `__file__`, боевой корень вычищается из
`sys.path` (иначе прогон «до» тянул бы модули из живого дерева).

## 7. Остатки (на 14.08.2026)

* **Зеркала ПК-полосы не требуется** — квитанция ТО живёт только в `splinter` на VPS.
* Дверь числа (`handle_service_result`, ответ доверенного числом) за 74 суток не срабатывала ни
  разу — она исправлена по коду и покрыта тестом, живым случаем не проверена.
* Частичных квитанций (часть записана, часть нет) в корпусе 0 — ветка хвостов доказана тестом,
  не живым случаем.
* Тайские формулировки — короткие и однозначные, но носителем языка не вычитаны.
* Класс «фикс в git ≠ фикс в проде» **ДЕЙСТВУЕТ**: код живёт в памяти процесса `splinter`,
  доставка = рестарт сервиса.
