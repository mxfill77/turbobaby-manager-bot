## 1. ЧТО ИМЕННО ПОДКЛЮЧЕНО

Пять классов, каждый — предикат над РАЗОБРАННОЙ командой, не над подстрокой
(`posttool_feed._CLASSES`, порядок = порядок проверки):

| класс | что считается событием | что событием НЕ является |
|---|---|---|
| `рестарт/старт/стоп клиентского бота` | `systemctl <restart\|start\|stop\|kill\|try-restart\|reload-or-restart\|force-reload> splinter` (в т.ч. под `systemd-run`); ПК-формы: `pkill/killall/taskkill` с именем `userbot_listen`/`moderation_bot`/`moderbot`, запуск этих же скриптов питоном | `systemctl show/status/is-active/cat splinter`; `orchestrator-daemon`; `wa-webhook`; `splinter-health` |
| `стирание маркеров гарда` | `rm/rmdir/unlink/shred`, `find … -delete/-exec rm`, `git rm` с целью внутри каталога маркеров (боевой `/tmp/cc_guard_block` **и** настроенный `block_dir()`) | `ls`/`cat`/`grep` по тому же каталогу; уборка своего черновика в `/tmp` |
| `вынос теста из гейта` | `mv`/`git mv`, где источник — `tests/test_*.py` (или каталог `tests` целиком), а место назначения этому глобу уже не отвечает | переименование ВНУТРИ `tests/test_*`; внос теста В гейт |
| `отброс рабочего дерева` | `reset --hard`; `checkout … --` и `checkout .`; `restore` (кроме голого `--staged`); `stash` (кроме `list/show/pop/apply/branch`); `clean -f` без `-n` | `stash list/pop`; `clean -n`; `checkout -b`; `checkout <ветка>` |
| `push в <удалённый>` | `git push` в любой форме, включая `git -C <репо> push` и `git -c core.hooksPath=… push` | `git push --dry-run`; `git stash push` (это отброс дерева) |

**Форма судится по ДЕЙСТВИЮ.** Разбор идёт по сегментам цепи и по ГОЛОВЕ сегмента — тем же
парсером, что у гарда (`_del_units`/`_cmd_index`/`_base`/`_del_targets`): текст коммита, шаблон
поиска и аргумент журнальной команды остаются одним `shlex`-токеном и головой сегмента не бывают.
Поэтому молчат `cclog.py "…нужен systemctl restart wa-webhook…"`, `grep -o "git checkout…"` и тело
коммита, дословно перечисляющее `git reset --hard` и `rm /tmp/cc_guard_block/*.json`.

**Гард для ленты — БИБЛИОТЕКА РАЗБОРА, а не исполнитель.** Из него зовутся ровно восемь
read-only имён (`is_probe`, `is_test_run`, `block_dir`, `GUARD_BLOCK_DIR`, `_del_units`,
`_del_targets`, `_cmd_index`, `_base`) и ни одной пишущей/решающей ветки (`decision`, `classify`,
`_guard_write_marker`, `_push`, `_card`). Стережёт это **ast-разбор файла ленты** — секция (8)
`tests/test_feed_list.py`, а не обещание в докстринге.

**Категории §4 «не уведомляем» — ноль во всех** (коммит, записи в мозг, гейт, копирование,
рестарт демона проверены отдельным фильтром по тем же командам).

### 2.1 Проект обещал 4.0/сутки, вышло 6.6 — и это не ошибка реализации

Расхождение целиком в классе push: §3.3 проекта насчитал **11** push за 120 ч, живой
классификатор — **21**. Проверены обе гипотезы (`_scratch_feedlist_0804/push_check.py`):

* **дублей транскрипта НЕТ** — 33 попадания, 33 уникальных `id` вызова, повторов ноль;
* **счёт проекта пропускал push внутри цепи.** Его классификатор возвращал ПЕРВЫЙ совпавший
  сегмент, поэтому `git add … && git commit -q -m "…" && … push …` записывался как «коммит», а
  push терялся. Живой пример из окна: 08-02 20:21, один вызов, оба действия внутри.

Правило 7 дисциплины среды («сводка — гипотеза, числа — факт») применяем к самому проекту:
**верное число push за 120 ч — 21 (4.2/сутки), а не 11 (2.2/сутки)**, и ожидаемый объём ленты —
**6.6/сутки, а не 4.0**. Это ВНУТРИ порога §6 («выше 8 = список раздут, режем»), но выше
обещанного. Список не режем молча — он утверждён владельцем; корректив у проекта уже прописан:
условие отзыва push-класса (§3.3) и смерть класса без реакции за 14 суток (§4). Первый кандидат
на сокращение, если владелец скажет «шумно», — именно push.

## 3. ЧЕСТНЫЙ ПРЕДЕЛ ШАГА 1 СНЯТ: ФОРМА ОТВЕТА ИНСТРУМЕНТА ИЗМЕРЕНА

Шаг 1 писал: «точную схему `tool_response` для Bash проверить нечем». Теперь проверено по живому
транскрипту (`_scratch_feedlist_0804/schema.py`, `schema2.py`): движок кладёт в
`toolUseResult` тот же объект, что уходит хуку.

| исход | что приходит | что говорит заметка |
|---|---|---|
| успех (187 случаев) | `{stdout, stderr, interrupted, isImage, noOutputExpected}` — **кода возврата НЕТ** | «выполнено» (без утверждения об успехе) |
| команда упала | **СТРОКА** `"Error: Exit code N\n<вывод>"` | «ошибка (код N)» |
| прервано | `interrupted: True` | «прервано» |
| отказ движка | строка `"Error: This command requires approval"` / `"Error: Contains simple_expansion"` — **без кода** | **заметки нет ВОВСЕ** |

Последняя строка — новое правило и главный вывод замера. До него `outcome` на любой строке
отвечал «выполнено»: заметка сказала бы «push выполнен» о push, которого не было. Для канала,
чьё единственное содержание — «мир изменился», это худшая из возможных ошибок. Теперь
`refused()` отличает отказ (не исполнялось → молчим) от падения (исполнялось → называем код);
таймаут отказом не считается. Побочная польза: **push, отбитый гейтом, честно назван ошибкой**.

## 4. ДЕТАЛЬ PUSH: ВЕТКА · СКОЛЬКО КОММИТОВ · ДИАПАЗОН · ⚠️

§3.3 проекта требует «одну строку на push, а не одну на коммит». `push_detail` берёт диапазон из
ответа инструмента (`   1c23895..fc07efa  main -> main`) и дочитывает у git ЧИСЛО, а не оценку:
`rev-list --count` и `diff --name-only` (read-only, таймаут 4с, любой сбой → деталь короче, но
заметка уходит). Пометка `⚠️ среди файлов машинерия защиты` ставится, если в диапазоне есть
`pretool_guard.py`, `orchestrator_daemon.py`, `devbot.py`, `gate.py`, `posttool_feed.py`,
`card_duty.py`, `notify.py`, `invariants_check.py`, `headless_settings.json`, `tests/`,
`deploy/hooks/` — ровно тот довод, ради которого класс и включён (26 из 31 коммита окна проекта
переписывали собственные предохранители системы).

**Дедуп научился различать разные push.** Отпечаток теперь включает деталь: два push подряд одной
и той же командой — ДВА разных факта мира (разные диапазоны), и глушить второй нельзя. Для классов
без детали отпечаток прежний.

   ПК-полосы этим НЕ доказано.
3. **`wa-webhook` в списке нет намеренно** — владелец назвал клиентского бота, транзит WA в §3 не
   входит. Расширять список молча нельзя: у класса без реакции по §4 наступает смерть, а не рост.
4. **Изоляция проб может проглотить настоящее событие.** Ручка одна и гардова (это осознанное
   решение шага 1): команда, запущенная из `/tmp/tb_scratch` или несущая `_test`/`_dryrun` в имени
   .py-файла ЛЮБОГО сегмента цепи, читается как проба. Цена: отброс дерева, сцепленный с прогоном
   такого файла, промолчит.
5. **Потолок 6 заметок на задачу** остаётся с шага 1. В сутки с 10 push (04.08) потолок может
   срезать хвост, если все они внутри ОДНОЙ задачи; замер такого случая в окне не показал.
6. **`git push` из скрипта/питона лента не видит** — судится команда оболочки. Живых случаев в
   окне нет; появятся — класс придётся учить телу (образец: `_py_dels` у гарда).
