# Минимум красной карточки + извлечение объекта (29.07.2026)

Правка делалась на ПК в клоне репо: задача пишет ТЕКСТ красных карточек и на VPS трижды убивала
себя собственной карточкой. Боевые операции ниже названы `<OP>`/сокращённо — по правилу репо
(см. docstring `tests/test_pretool_script_args_guard.py`).

## Что изменено

1. **Карточка = четыре подписанные строки** (`pretool_guard._card`): `Что:` → `Объект:` → `Число:`
   → `Откат:` (+ `Проверь: … жду твоё «да».`). Абзац `Последствия:` убран — стоимость ошибки
   честнее показывает ОТКАТ, а карточка обязана читаться за три секунды.
2. **Нет ОБЪЕКТА или ЧИСЛА → карточки нет вовсе** (`card_min` + ветка в `main()`): вместо карточки
   строка `card_skipped` в `GUARD_LOG`. Ни пуша владельцу, ни маркер-конверта демону.
   Решение хука НЕ слабеет: остаётся `ask` — без «да» команда не исполняется.
   **Жёсткий блок — исключение:** `deny` и hard-маркер приходят всегда.
3. **Извлечение объекта переписано на ЖИВЫЕ имена полей Bridge** (`_detail_parts`).

## Корень: почему объект «находился всегда»

Две течи одного класса («мок ≠ живой формат»), обе в извлечении, а не во второй линии:

* «есть ли объект» решала `marker_has_object` — регулярка `\d` по ТЕКСТУ ГОТОВОЙ карточки.
  Шаблон операций с парком несёт «Лист**1**» → цифра там есть **всегда** → объект «найден» всегда.
* само извлечение искало `plate=` / `client=` / `wallet=` / `\bkm=`, тогда как `bridge_client`
  зовётся `number=` / `name=` / `group=` / `oil_km=`. Совпадений — ноль, объект не извлекался
  **ни разу** (плюс `\bkm` физически не совпадает внутри `oil_km`: подчёркивание — словесный символ).

`marker_has_object` оставлена как вторая линия без изменений; первая линия теперь выше неё.

## Последствие, которое стоит решить владельцу

Ядро красной зоны (Лист1/CRM/деньги) карточку сохраняет. Периферия — теряет (замер прогоном):

| операция                        | карточка   | объект / число                        |
|---------------------------------|------------|---------------------------------------|
| ТО масло, живой вызов           | ЕСТЬ       | байк 6789 / пробег 27000              |
| касса, живой вызов              | ЕСТЬ       | кошелёк Наличка / сумма −500          |
| закрытие аренды                 | ЕСТЬ       | байк 6334, клиент Jack / сумма 2500   |
| удаление события                | ЕСТЬ       | событие −100123:456 / ключ            |
| kill по PID                     | ЕСТЬ       | цель kill … 4242 / PID 4242           |
| отмена последней проводки       | **в журнал** | кошелёк Наличка / — (числа нет вовсе) |
| стоп чужого сервиса (по имени)  | **в журнал** | цель … stop nginx / —                 |
| pkill по имени процесса         | **в журнал** | цель pkill −9 chrome / —              |
| SQL-запись в чужую БД           | **в журнал** | таблица bikes / —                     |

Четыре нижние строки — операции, у которых ЧИСЛА не существует в принципе. Правило «нет объекта
ИЛИ числа → карточки нет» применено буквально, как заказано. **Развилка:** если владелец хочет
видеть их карточками — нужно исключение «числа у операции нет by design» (одна строка в `card_min`).
До решения они остаются `ask` + строкой в журнале.

## Классификатор «текст о действии vs действие» — НЕ ТРОГАЛ (честный отказ)

Замер `classify()` (чистая функция, ничего не исполнялось):

| команда                                             | класс |
|-----------------------------------------------------|-------|
| heredoc пишет ФАЙЛ теста, внутри тела шебанг python  | RED   |
| heredoc пишет файл БЕЗ шебанга                       | green |
| python-heredoc записывает фикстуру в файл            | RED   |
| `python3 -c "print('<OP>(number=…)')"` — печать      | RED   |
| `python3 -c "<OP>(number=…)"` — исполнение           | RED   |
| `python3 -c "bridge.call('<OP>', number=…)"`         | RED   |
| `git commit -m "… <OP> …"`                           | green |
| журнальная строка в argv, `grep` по исходнику        | green |
| свой тест гарда                                      | green |

Строки 4 и 5 различаются **только** обёрткой `print(` — текст и действие текстуально изоморфны.
Строка 6 добивает: в этом репо боевая операция **штатно передаётся строкой в кавычках** диспетчеру,
то есть эвристика «красное слово внутри строкового литерала = данные» здесь ровно наоборот — она
открыла бы дыру в живом стиле вызова.

Прежние фиксы этого класса (`_strip_search_pattern`, `_strip_script_cli_args`) безопасны потому,
что судят **позицию** (конкретный слот argv конкретной команды), а не содержание. У heredoc/`-c`
такого слота нет: тело и ЕСТЬ исполняемая программа. Рассматривал сузить `_is_python` до
структурного (интерпретатор — слово-КОМАНДА сегмента, а не любой токен): это сняло бы строку 1,
но не строки 3–4, зато затронуло бы точку входа всей классификации без возможности прогнать её на
живом трафике. Вывод: **надёжно не отличить, оставлено как есть** — лучше, чем открыть дыру.

Побочно правка минимума часть самоубийств снимает: безобъектный «текст о действии» (упоминание
операции без полей) больше не даёт ни карточки, ни маркер-конверта демону — а именно маркер
обрывал живую задачу. Фикстура, скопированная с живого формата (с `number=`), карточку по-прежнему
даёт: это цена правила «мок обязан копировать живой формат».
