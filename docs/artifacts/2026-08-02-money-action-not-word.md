## 2. Что стало

### 2.1 Красное денежного класса — только признак действия

`_money_is_action(tok, raw, view, blind)`; решает РАЗБОР тела (`_py_code_view`, ast), а не подстрока:

1. **разобранный вызов** — `bridge.add_transaction(…)`, `void_last(…)` (`view["calls"]`);
2. **имя кода** — ссылка/импорт/атрибут без скобок (`fn = bc.void_last`, `from … import …`)
   (`view["names"]` — новый факт разбора: идентификаторы БЕЗ строковых литералов);
3. **литерал-селектор + канал** — строка отдана вызову (`_post("<OP>", …)`,
   `data={"action": "<OP>"}`, `getattr(bc, "<OP>")`) И у тела есть чем дойти до кассы
   (`view["lit_args"]` + `view["channel"]`).

**Канал** = импорт вне белого списка чисто-разборных модулей (`_INERT_MODULES`: re, json, os,
datetime, glob…) ЛИБО вызов исполняющего/сетевого имени (`_EXEC_CALLS`: system, popen, run,
urlopen, post, getattr…). Список белый НАМЕРЕННО: неизвестный модуль считается каналом, сомнение
решается краснее.

**Литералы собираются только из АРГУМЕНТОВ вызова** и только на глубину контейнера
(`_str_consts`, список/кортеж/словарь). Поэтому `any(t in line for t in ("<OP>", …))` —
генератор, а не аргумент — действием не считается: ровно эта форма и убила 117/140.

### 2.2 Fail-closed там, где разбирать нечего

| ситуация | поведение |
|---|---|
| тело не разобралось (обрыв, чужой синтаксис) | прежняя подстрока, байт-в-байт |
| слепое тело: `python3 - <<EOF`, неизвестный `-m`, нечитаемый `.py` (`amb`) | прежняя подстрока |
| имя произнесено ВНЕ разобранных тел (до имени скрипта, в обёртке) | прежняя подстрока |
| команду не разобрал даже шелл (`shlex` упал) | прежняя подстрока (добавлено отдельной веткой) |

Подстрока берётся по СКАН-представлению, а не по сырой команде: класс «данные ≠ команда» (argv
журнального скрипта, шаблон `grep`) цел — это поймали регрессы `test_guard_cli_args` и
`test_pretool_script_args_guard`, и они же его сторожат.

### 2.3 Объектный гейт распространён на деньги

`_ALWAYS_CARD` снят (не переименован — `not hasattr` проверяется тестом). `card_gate` и
`marker_has_object` теперь говорят одно и то же ВСЕМ классам: нет названной цели — карточки нет,
есть строка в журнале гарда; решение хука (`ask`) при этом не слабеет.

Прежнее основание исключения — «`void_last()` по природе зовётся без аргументов, извлекать
нечего» — оказалось ложным: **цель у такого вызова есть, это САМ ВЫЗОВ**. `_money_call_seen`
называет её «вызов void_last()», и настоящая отмена спрашивает как прежде.

Объект денежной операции собирается в ЖЁСТКОМ порядке источников:
**разобранный литерал аргумента → «значение вычисляется» → текст (только если вызова в разборе
нет вовсе)**. Иначе регулярка `ключ=значение` читает весь blob и на теле
`wallet = input()` + `add_transaction(group=wallet, …)` выдавала «кошелёк **input**» — имя
ПЕРЕМЕННОЙ вместо цели (найдено прогоном, а не рассуждением).

## 4. Остаток, названный числом и адресом

Команда 117 после правки — **`journal[create_booking]`**, а не `defer`: тот же список слов
содержит имена операций ЖИВЫХ ТАБЛИЦ, и для них асимметрия «строка МОЖЕТ быть действием»
сохранена намеренно (`_body_has`, ветка не-денежных токенов). Владельца это больше не будит
(объекта нет → карточки нет), но команда без «да» не идёт, а в headless «да» некому дать.

**Точка касания, если владелец решит закрыть и это:** `pretool_guard._body_has` — распространить
`_money_is_action` на `_HITS_FLEET`/`_HITS_CRM`/`delete_event`. Почему НЕ сделано здесь: ТЗ
ограничило правку денежным классом, а у операций живых таблиц сомнение доктринально решается
краснее (запись в Лист1/CRM — высшая цена ошибки, и там ложное красное стоит одной задачи, а
пропуск — чужого труда).

## 6. Изоляция проб внутри живой задачи — чем правильно заменить признак (без правки)

**Диагноз.** Все три звена изоляции висят на `is_test_run()`, то есть на ОКРУЖЕНИИ, а демон
намеренно снимает тест-флаги с окружения боевого `claude -p` (иначе боевая задача притворилась бы
тестом). Значит у пробы внутри живой задачи нет способа сказать «я проба» — признак описывает
РЕЖИМ ПРОЦЕССА, а владельца интересует не режим.

**Замена, по силе:**

1. **ГЛАВНОЕ — признак должен описывать ЦЕЛЬ ОПЕРАЦИИ, а не режим прогона.** Карточка владельцу
   нужна тогда и только тогда, когда операция называет ЖИВУЮ сущность. Механика уже есть
   (`_extract_first_entity`/`_is_test_entity`/`_entity_blocktype`), но работает односторонне:
   живая сущность → жёсткий блок, тест-сущность → мягкая карточка. Достроить симметрию:
   **тест-сущность → журнал, без карточки** — владельцу в ней решать нечего. Тогда проба внутри
   живой задачи гасится сама, без единого флага. Условие честности: сущность должна проверяться
   ФАКТОМ, а не словом, — «номера нет в живом парке», «кошелька нет в кассе» (read-only сверка),
   а не префикс `ТЕСТ` в имени. Иначе мы заменим один корень А другим.
2. **Самообъявление пробы, симметричное `DOWRITE`.** У нас уже есть маркер «этот скрипт реально
   пишет», который судится по сырому тексту намеренно. Зеркало — `PRETOOL_TEST_RUN=1` ПРЕФИКСОМ
   В САМОЙ КОМАНДЕ: он принадлежит команде, а не унаследованному окружению, поэтому демон его не
   снимает, и `_cmd_declares_probe` его уже понимает. Практический шаг — вписать этот префикс в
   headless-преамбулу рядом с `PRETOOL_NOPUSH=1` как ОБЯЗАТЕЛЬНЫЙ для любой пробы. Предел назван
   прямо: самообъявление может лгать, поэтому оно не смеет ослаблять РЕШЕНИЕ (`ask` остаётся) —
   только канал владельца, ровно как сейчас делает `_probe_intercept`.
3. **Место запуска.** `/tmp/tb_scratch/` уже считается пробой (правило R17). Слабое звено — сама
   R17 не соблюдается: разведка живёт в `_scratch_*/` внутри репо (в том числе в этой задаче).
   Либо привести практику к R17, либо научить `_is_test_script` каталогам `_scratch*` — это
   конвенция, а не факт, поэтому третьим номером.

**Чего делать НЕЛЬЗЯ:** возвращать тест-флаги в окружение боевой задачи. Демон снимает их не по
недосмотру — это единственное, что мешает живой задаче объявить себя тестом и молча писать в
живые таблицы.
