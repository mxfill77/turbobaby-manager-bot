## 2. ГЛАВНОЕ: сервер не может ПРОЧИТАТЬ общий репозиторий

Задание просит научить сводку судить по общему репозиторию и отдельно запрещает заводить,
просить и искать учётные данные. Замер показал, что **эти два требования несовместимы на этой
машине**: у сервера нет ни одного маршрута к общему репозиторию, который не требовал бы РОВНО тех
же учётных данных, что и запрещённый push.

Маршрут к общему репозиторию **ровно один** (`git config --get-regexp '^remote\.'`):

```
remote.origin.url    https://github.com/mxfill77/turbobaby-manager-bot.git
remote.origin.fetch  +refs/heads/*:refs/remotes/origin/*
```

Три независимые пробы, все — **чтение**, push не пробовался ни разу (прямой запрет задания):

| проба (только чтение) | результат |
|---|---|
| `GIT_TERMINAL_PROMPT=0 git ls-remote --heads origin` | `fatal: could not read Username for 'https://github.com'`, **exit=128** |
| `GIT_TERMINAL_PROMPT=0 git fetch --dry-run origin` | та же строка, отказ |
| анонимный GET `…/info/refs?service=git-upload-pack` | **HTTP 401 Unauthorized** |
| анонимный GET `https://api.github.com/repos/mxfill77/turbobaby-manager-bot` | **HTTP 404 Not Found** |

401 на git-плече и 404 на плече API — подпись **приватного** репозитория: неаутентифицированному
читателю GitHub отвечает «не найдено», а не «нельзя». Вывод, который и делает премису
неисполнимой: **чтение общего репозитория с сервера стоит тех же учётных данных, что и запись.**
Отбита не отправка — отбит доступ целиком.

Других копий репозитория на машине нет: `/root/tb_wt_expect_0807_z8k3/.git` — рабочее дерево
прошлого захода, не зеркало общего репозитория.

## 4. ЛОВУШКА ДЛЯ СЛЕДУЮЩЕГО ЗАХОДА: `origin/main` — это НЕ общий репозиторий

Самое опасное в этой задаче — то, что она выглядит уже решаемой: `origin/main` на сервере
существует, читается мгновенно и называется именем общего репозитория. **Это замороженный кэш, а
не общий репозиторий.** `git reflog show origin/main` показывает, что все его обновления —
`update by push`, и последнее из них датировано **30.08 13:38** (`e646f1f`). То есть ссылка
двигалась только тогда, когда push с сервера ещё проходил, и застыла в момент, когда он перестал
проходить.

Отсюда прямое следствие, которое стоит назвать вслух: **наивная правка «судить по `origin/main`»
не починит класс, а переоденет его**. Сводка будет уверенно докладывать «работа не уехала,
отстаём на 4 коммита от общего репозитория», ссылаясь на «общий репозиторий», которого она не
читала с 30.08. Сегодняшняя ложь произносится хотя бы от своего имени («мой push отбит»); та была
бы ложью со ссылкой на несуществующее наблюдение — то есть строго хуже.

Это же и есть предсмертный взгляд задания, только с другой стороны: второй источник правды,
расходящийся с первым молча, здесь **уже лежит на диске** и не требует заводить файл-отметку.

## 6. Развилка владельца (называю, не выбираю и не делаю)

1. **Дать серверу право ЧТЕНИЯ** (read-only deploy key / read-only токен). Это единственный ход,
   после которого пункт 4 задания становится исполнимым буквально. Это учётные данные — заводить
   их исполнителю прямо запрещено, решение владельца. Отдельно стоит заметить, что право чтения
   строго уже права записи, которого мы сознательно избегаем.
2. **Пусть отметку о доставке кладёт ПК** — тот, кто общий репозиторий видит. Честнее, чем догадка
   сервера, но это ровно второй источник правды из предсмертного взгляда: он умеет протухнуть
   молча, и его придётся снабжать возрастом и третьим исходом.
3. **Не учить сводку судить по общему репозиторию вовсе, а перестать врать.** Сводка убирает
   утверждение «работа не уехала» и просьбу об учётных данных, и говорит то, что есть: отправка
   сервера отбита, судьба работы отсюда **не видна**, увозит её доставка с ПК. Это выполняет
   первое предложение цели («перестаёт просить учётные данные, которых схеме не нужно») и честно
   не выполняет второе. Единственный вариант, не требующий ни учётных данных, ни второго
   источника правды.
