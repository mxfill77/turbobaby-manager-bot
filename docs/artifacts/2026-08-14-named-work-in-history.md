## 2. Место подмены — строкой кода

`splinter._sp_write_done`, ветка «регистра нет» (до правки):

```python
lbl = _SP_KIND_LABEL.get(k, (k, k))[1]
bridge.add_event(..., notes=f"{lbl} — {odo_int} км",
                 msg_id=f"sp:{chat_id}:{topic_id}:{k}:{odo_int}")
```

`k` — не работа, а **вид** работы. Свёртка происходит раньше, в `_declared_kinds`: каждое `w` из
`works` заменяется на `_service_kind(w)`, и дальше по всей двухфазной цепи едет только ключ.
Слова при этом не терялись — они лежали в `WORKS:{…}` поля `note` заявки (кладёт
`_sp_note_set_works`, Z4) и в карточке байка (`splinter` 1997). В историю не шло ни одно.

## 3. Забор Честертона: зачем ярлык нужен

Ярлык **не снят** — на нём висит то, чего слова механика нести не могут:

| что | где | почему ключ |
|---|---|---|
| адрес записи | `_SP_COL_KINDS` → `set_fleet_oil`/`set_fleet_service` | столбец Лист1 I/J/K/L выбирает ключ |
| расчёт регистров | `_service_interval(k…)`, `service_upsert(service_type=k…)` | остаток до ТО считается по ключу |
| идемпотентность | `msg_id=sp:{chat}:{topic}:{k}:{odo}` | та же работа ДРУГИМИ словами не должна дать вторую строку |
| два языка | `_sp_labels_ru/th` (8+ мест) | слова механика существуют ровно на одном языке |
| дедуп и отмена | `_SVC_WRITE_DEDUP`, позиции `undo_last` | ключуются видом |

Правило: **ярлык — машине, слова — человеку**. Меняется ровно текст `notes` — единственное поле,
которое читает человек и не читает ни один расчёт.

## 4. Что сделано

`work_name.py` — чистая функция «вид + слова механика → строка истории», **импортов ноль**
(страж `WORK_NAME_PURE`, ast, в гейте). Слова этого вида = те `w`, которые **живой**
`_service_kind` свернул в тот же ключ; своей копии правил в модуле нет.

Исхода два, и разница видна в самой строке:

* **названа** → идут слова механика («замена аккумулятора — 36474 км»);
* **не названа** → ярлык, **байт-в-байт прежняя строка** («прочие работы — 36474 км»). Ярлык
  категорией себя и называет; второго, придуманного нами слова о незнании в таблицу не кладём.

Слова читаются **лениво и только из этой ветки**: колоночный путь не платит ни одного лишнего
обращения к мосту (счётчик вызовов в тесте). Дверь голого числа доверенного передаёт слова из
уже прочитанной заявки — мост не спрашивается второй раз.

байт-в-байт прежний (доказано тестом на том же дословном случае).

гейт полный **207**, храповик слепых читателей 72 без прироста.

## 8. Остатки

* Дверь `_write_service_col` (кол. J/K/L кнопкой «Зафиксировать») этой ветки не проходит вовсе —
  у неё регистр есть; истории она и не писала.
* Слова берутся из **открытой** заявки: работа, названная после закрытия заявки, в строку не
  попадёт (точка касания — `_sp_words_said`).
* Вид, опознанный только сканом свободного текста (`_SP_TEXT_KINDS`), слов не имеет по
  построению → ярлык; 1 случай из 3 в замере именно такой.
* Класс «фикс в git ≠ фикс в проде» **ДЕЙСТВУЕТ** — код в памяти процесса `splinter`, доставка =
  рестарт сервиса, а он этим заданием запрещён (идёт карточкой по вердикту О3).
* Зеркала ПК-полосы не требуется — запись ТО живёт только в `splinter` на VPS.
