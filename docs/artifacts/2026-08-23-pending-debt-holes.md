## §1. ЧТО ИМЕННО БЫЛО СЛОМАНО И ЧЕМ ЧИНИТСЯ

Общий корень у всех шести один и он в устройстве листа: **строка «то_заявки» одна на пару
тема × байк**. `servicePendingFind_` ищет открытую строку по `chat+topic+bike`, а
`servicePendingUpsert_` кладёт `declared`/`done`/`status`/`odometer` ЦЕЛИКОМ (`pick`,
`bridge_prod/ServicePending.js:55`). Долг, стоявший на этих полях, принадлежал не работе, а БАЙКУ —
и потому доставался тому, кто приехал последним.

| № | дыра (ревизия) | чем закрыта |
|---|---|---|
| 1 | следующий визит того же байка затирал висящий долг (Н5) | позиции долга переехали в `note` — единственное поле, которого визит не передаёт; сторож выбирает ветку по СЛЕДУ, а не по статусу |
| 2 | партия из двух позиций гасла по первой записи (Н3) | `service_debt.settle` снимает РОВНО доказанные позиции; остальные остаются висеть |
| 3 | вторая дверь закрытия мимо вердикта (Н4) | `_sp_write_done` закрывает через `_sp_debt_close`; прямой `close` остался только в ветке отката `SERVICE_DEBT=0` |
| 4 | безусловное закрытие дописывало строку-эхо (Н1) | перед закрытием дверь СПРАШИВАЕТ, есть ли что закрывать; строки нет → ни одной записи |
| 5 | закрытие гасило ЧУЖУЮ открытую строку (Н2) | своя — та, что называет хоть одну закрываемую позицию; иначе строку не трогаем |
| 6 | — | отрицательные тесты на каждый пункт + близнец «то же без порчи проходит» |

**Носитель выбран не по вкусу, а по свойству мира** (доказано node-харнессом на ЖИВОМ
`bridge_prod/ServicePending.js`, §3): визит соседа поля затирает, а ноту сохраняет.

Форма — зеркало уже живущего в том же поле сегмента `WORKS:{…}`:

```
DEBT:{abs@41357; pads@41357} | WORKS:{замена тормозной жидкости; …} | escalated
```

Соседи по ноте не теряются никогда (`_rest_of`). **`DEBT:{}` — не мусор, а слово**: пустую строку
мост читает как «поле не передали», то есть стереть ноту нечем, и «позиций больше нет» можно
сказать только непустым. Сторож по этому признаку возвращает строку прежнему пути.

**Строка закрывается, только когда за ней не осталось НИ ОДНОГО обязательства** — ни позиции долга,
ни заявленного без отписки (`declared` минус `done`). Исключение ровно одно и названо:
`row_terminal` — дверь фазы 2 («да» доверенного) и есть терминал самой заявки, у неё «не сделано»
законный исход, а не висящий хвост. Забор Честертона не снят: голден на это стоит отдельным тестом.

**Разделение обязанностей не размыто:** `verdict` отвечает «долг закрыт ли» (три признака, возраста
среди параметров нет вовсе), `settle` — «чья строка и какая позиция». Двух ответов на один вопрос не
заводится. Импортов у решения по-прежнему **ноль** (страж `SERVICE_DEBT_PURE`, ast, в гейте):
регулярок нет, разбор сегмента на строковых операциях.

## §3. ХАРНЕСС НА ЖИВОМ КОДЕ МОСТА (`tests/pending_debt_harness.js`)

Мост в этом заходе не правится и не выкладывается, поэтому харнесс проверяет не лечение, а
**свойства мира, на которых лечение стоит**: 16 проверок, из них **8 отрицательных**, у каждой
близнец. Исполняется РЕАЛЬНЫЙ `bridge_prod/ServicePending.js` (+ `Config`/`BotData`/`ReadFleet`) в
node на мок-листе; в Google не ходили.

| проверка | что показал живой мост |
|---|---|
| `carrier.survives_visit` | визит соседа ноту СОХРАНЯЕТ (`pick` берёт из `cur`) |
| `fields.done_overwritten` · `fields.odometer_overwritten` | `abs,pads@41357` → `gear@41641` в ТОЙ ЖЕ строке — дословная судьба 5960 |
| `echo.close_without_row_appends` | закрытие без открытой строки ДОПИСЫВАЕТ строку (`saved`), declared и done пусты |
| `echo.twin_existing_row_is_updated` | строка есть → та же дверь её обновляет: забор не отнимает законного закрытия |
| `alien.chain_claim_is_extinguished` | закрытие гасит ЛЮБУЮ открытую строку пары — мост не спрашивает, чья работа |
| `alien.twin_other_bike_untouched` | по другому байку строка цела: ключ мост держит, работу — нет |
| `empty.note_cannot_erase` / `empty.twin_word_can` | пустая нота не стирает; `DEBT:{}` стирает |
| `list.carries_note` · `get.carries_note` | сторож и дверь ноту ВИДЯТ; закрытая строка из открытых уходит |

Вывод харнесса и есть обоснование, почему лечение целиком питоновское: решать «есть ли что
закрывать» и «своё ли это» может ТОЛЬКО вызывающий.

## §6. ОТКАТ И ОСТАТКИ

**Откат — `SERVICE_DEBT=0` + рестарт `splinter`**: гаснет и след, и дверь вердикта; `_sp_write_done`
возвращается к прежнему прямому закрытию с прежней нотой `written=… by …` (доказано тестом:
ноль обращений к миру, нота начинается с `written=`).

**ОСТАТКИ (на 23.08.2026, `docs/artifacts/2026-08-23-pending-debt-holes.md`):**

* **В ПРОДЕ ЭТОГО НЕТ.** Класс «фикс в git ≠ фикс в проде» ДЕЙСТВУЕТ: код живёт в памяти процесса
  `splinter`, доставка = рестарт сервиса, а он этим заданием прямо запрещён. До доставки все шесть
  дыр в проде открыты ровно так же, как их описала ревизия.
* **Дверь вердикта платит одно ЧТЕНИЕ там, где раньше платила слепую ЗАПИСЬ.** Цена названа, а не
  спрятана: на успешном пути записи это +1 обращение к мосту (было 1 POST, стало 1 GET + 1 POST),
  зато исчезли записи там, где закрывать нечего. Точка касания — `_sp_debt_close`; сторож за второе
  чтение не платит вовсе (строку он держит в руках и передаёт параметром `row`).
* **Позиция закрывается ПАРТИЕЙ у признака клетки.** `_sp_debt_cell` берёт слабейший регистр и
  закрывает все названные позиции разом по наибольшему требованию следа. Это консервативно (закрыть
  труднее), но не позиционно: клетка `gear` ≥ своего числа при не легшем `abs` строку не закроет, а
  вот две колоночные позиции с РАЗНЫМИ числами закроются вместе по большему. Точка касания —
  `_sp_debt_cell` и ветка `cell` в `_sp_debt_voice`.
* **Строка «долг закрыт: <признак> — <почему>» из ноты ушла.** Прежняя запись затирала ноту целиком
  (вместе с `WORKS:{…}`); теперь причина живёт в журнале, а в ноте — только след и соседи. Это
  осознанный размен: `WORKS` читает карточка «в работе», причина не читается никем.
* **Слитая строка остаётся в статусе `ждёт_подтверждения` после снятия позиций.** Ветку выбирает
  след (`DEBT:{}` → прежний путь), но сам статус мы не переводим назад в `ждёт_факт` — это была бы
  правка чужого визита. Точка касания — `_sp_debt_close`, ветка `close_row=False`.
* **Зеркала ПК-полосы нет** — долг живёт только в `splinter` на VPS (точки касания на той стороне,
  если понадобится: форма сегмента, дверь закрытия, выбор ветки сторожа).
* **R17 нарушен вынужденно и назван:** разведка в `_recon_debtholes_0823/` (там же временное дерево
  `git worktree`), потому что песочница движка запретила `mkdir` во временном каталоге дословно.
  Каталог не удалялся — удаление вне временных каталогов красное.
