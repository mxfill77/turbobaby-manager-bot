# Возраст тика ревизора называется рядом с его временем (14.08.2026)

**Заход:** куратор цели 531, шаг 2, глубина 2 · полоса vps · `devbot` (живёт внутри процесса
`bot.py`) · чистая функция `revizor_age.py`.
**Повод:** остаток §6 прошлого захода того же класса —
`docs/artifacts/2026-08-14-revizor-tick-reader-contract-vps.md`: «доска честно показывает дату
последнего тика, но „тик молчит N часов“ никого не будит».

## 1. Класс

Строка доски владельца (единая команда «статус» в теме 328) печатала **время** последнего тика
ревизора и молчала о его **возрасте**:

```
👁 надзор: ревизор 2026-08-13 13:26 — окон 1
```

14.08 в 10:32 UTC этой строке шёл **двадцать первый час**, и по ней это было неотличимо от
свежего тика. Род тот же, что у «нуля по неразбору» (`scan_result`, `205c00b`), и чинится так же:
не разбором (он верен — штамп прочитан правильно), а тем, **что читатель обязан сказать вслух**.
Наверх уходило число, а вопрос читающего — «этому числу можно верить СЕЙЧАС?» — оставался без
ответа.

## 2. Замер (живой `cowork_log` через мост, 14.08.2026 10:32 UTC)

Тики берутся **живым** шаблоном читателя доски `devbot._REV_NOTE_RE` — второй копии шаблона не
заводится.

```
непустых строк : 976
тиков          : 37   (у всех 37 штамп с датой)
окно           : 400.2 ч = 16.7 суток   (28.07 18:23 → 13.08 13:26)
возраст свежего: 21.11 ч
```

Паузы между тиками (36 штук, часы), по возрастанию:

```
0.02 ×9 · 0.03 ×5 · 0.05 ×2 · 0.07 ×3 · 0.08 ×2 · 0.77
5.38 · 5.95 · 5.97 ×3 · 5.98 ×3 · 6.02 ×2 · 6.05
11.83 · 18.02 · 18.32 · 23.95 · 24.32 · 36.13 · 83.38 · 96.37
```

Форма **разделённая**: до 0.08 ч — тики внутри одного прогона ревизора; кластер 5.38…6.05 — его
штатный ход (≈6 ч); дальше **пусто до 11.83**, то есть «пропущен хотя бы один цикл».

## 3. Порог: 9 ч, а не 3 ч из задания — число измерено, а не выбрано

Порог стоит **в середине пустого промежутка 6.05…11.83** (ширина 5.78 ч) — тот же приём, что у
О3, О5 и порога веса серии. Устойчив к ±2.5 ч: при любом значении из промежутка пометку получают
**одни и те же 9 пауз из 37**.

| порог | доля времени под «⚠️ тик старый» | пауз с пометкой |
|------:|---------------------------------:|----------------:|
|  1 ч  | 94.6 % | 20 из 37 |
|  2 ч  | 89.6 % | 20 из 37 |
|  **3 ч** | **84.6 %** | **20 из 37** |
|  4 ч  | 79.6 % | 20 из 37 |
|  6 ч  | 69.9 % | 12 из 37 |
|  **9 ч** | **63 %** | **9 из 37** |
| 12 ч  | 56.4 % |  8 из 37 |
| 24 ч  | 36.0 % |  4 из 37 |

При пороге 3 ч, названном в задании, пометку получают **все одиннадцать штатных шестичасовых
пауз**, и доска несёт «⚠️ тик старый» 84.6 % времени окна — то есть пометка перестаёт что-либо
значить (ровно тот шум, за который 05.08 отозван класс push из ленты). При 9 ч доля 63 % высока
**честно**: в окне есть настоящие молчания 36, 83 и 96 часов и текущее 21-часовое.

**Число владельца остаётся в одной ручке:** `REVIZOR_TICK_HOURS=3` в `.env` — и порог снова 3 ч.

**Что лечит порог, а что — сам возраст.** Возраст печатается **всегда** (пока ветка жива), и
именно он закрывает класс: «13:26 (21 ч 6 мин назад)» прочесть как свежее нельзя ни при каком
пороге. Пометка «⚠️ тик старый» — второй, громкий слой, и порог отвечает только за него.

## 4. Решение

`revizor_age.py` — чистая функция «штамп + сейчас + порог → приписка к строке доски».
**Импорт ровно один** (`datetime`: разобрать штамп и вычесть его из **принесённого** «сейчас»).
Своих часов у решения нет — оттого тест пришпиливает время, а не гоняется за живыми часами.
Стережёт инвариант `REVIZOR_AGE_PURE` (ast, в гейте): один импорт, ни рук, ни обращений к часам.

**Исходов четыре, и «неизвестно» не запасное** (тот же замок против ложного зелёного, что у
`scan_result`, `write_fact` и О3):

```
fresh    возраст измерен, в пределах порога   → «(1 ч 34 мин назад)»
stale    возраст измерен, больше порога       → «(21 ч 6 мин назад ⚠️ тик старый)»
unknown  возраст ИЗМЕРИТЬ НЕЧЕМ                → «(возраст неизвестен: <почему>)»
off      порог 0                               → приписки нет, строка байт-в-байт прежняя
```

Причина незнания **различается** (штампа нет вовсе · даты в штампе нет · штамп в будущем ·
текущее время неизвестно): свернуть их в одну фразу — тот же грех, что свернуть промах в пусто.
Легаси-формат ПК без даты («13:26») моментом не становится: суток в нём нет, а подставить
«сегодня» значит выдать догадку за факт.

**Штамп в будущем.** Журнал пишет ПК минутной точности чужими часами, поэтому расхождение до
`SKEW_SEC` (5 мин) считается дрожанием часов и даёт «меньше минуты назад»; дальше — `unknown`.

**Приписка клеится вплотную к штампу**, а не в конец строки: возраст относится ко времени, а не к
числам окон — между ними не должно быть места для чтения «время старое, зато данные свежие».

Строка доски после правки (дословно, живой случай):

```
👁 надзор: ревизор 2026-08-13 13:26 (21 ч 6 мин назад ⚠️ тик старый) — окон 1
```

## 6. Границы и остатки

* **Ревизор и его проверки не тронуты**: правка живёт в читателе доски на VPS. Полоса ПК не
  тронута — **зеркала не требуется**: доска «статус» живёт только в `devbot` на VPS (тот же
  проверенный факт, что у читателя тика).
* **Откат — одна ручка:** `REVIZOR_TICK_HOURS=0` + рестарт `splinter` → строка доски байт-в-байт
  прежняя (доказано голденом на дословной строке).
* **Возраст считается от ШТАМПА, а не от факта тика.** Если ПК напишет строку задним числом или
  его часы уедут больше чем на 5 минут — возраст поедет вместе с ними; проверить штамп нечем,
  вторым источником времени тика мы не располагаем.
* **Молчание ревизора по-прежнему никого не будит.** Доска отвечает на «статус» по запросу; ждущей
  реакции (заметка/ожидание) на «тик молчит N часов» здесь не заведено — это ожидание О-ПК-3,
  точка касания `expectations._o4` (порог 16 ч ловит след ПК, а не тик).
* **Класс «фикс в git ≠ фикс в проде» ДЕЙСТВУЕТ**: `devbot` живёт внутри процесса `bot.py`,
  доставка = рестарт сервиса `splinter`.
