# `bridge_prod/` — зеркало ПРОД-моста под git (заведено 10.08.2026)

Здесь лежат исходники **задеплоенной** версии Apps Script проекта «TurboBaby Bridge» —
той самой, что обслуживает `BRIDGE_URL`. На момент заведения: **версия @79**, 17 файлов,
HEAD проекта совпадает с прод-версией (`MIRROR.json` → `head_equals_prod`).

## Зачем это здесь

До 10.08.2026 содержимого моста под версиями не было **нигде**: единственной локальной копией
была рабочая папка `clasp` — `/root/turbobaby-bridge-gs`, а она не под git и расходилась с продом
в обе стороны. Отсюда весь класс «папка выглядит готовой к выкладке, а на деле позади прода»:
заливка из неё стирала бы чужую работу молча, потому что вопрос «кто впереди?» приходилось решать
глазом — по `mtime`, `.bak`-снимкам и памяти исполнителя.

Теперь у вопроса есть **команда**:

```
venv/bin/python3 deploy/bridge_prod_diff.py [каталог-снимков]
```

Она снимает read-only отпечаток моста и сравнивает с этим зеркалом **два** живых состояния:
задеплоенную версию `@N` и **HEAD проекта** (третье состояние — его перезаписала бы заливка,
а по URL его не видно вовсе). Коды выхода: `0` — совпадает, `1` — расхождение названо поимённо,
`2` — отпечаток снять не удалось (тогда о состоянии прода **не заявляем**).

## Почему в зеркале ПРОД, а не собранная база

Собранная база заходá (например `/root/bridge-cellcontract-20260809-q7v4/build`) — **производная**:
она = прод + дельта захода, живёт один заход и умирает вместе с ним. Прод не выводится ни из чего
локального: это единственное состояние, ОТНОСИТЕЛЬНО которого измеряется «прод впереди».
Поэтому под версии положен он. Собранные базы под git не кладём — иначе зеркало начнёт значить
«что мы собирались выложить» вместо «что выложено», и вопрос снова станет неоднозначным.

## Это НЕ каталог выкладки

Здесь нет и не должно быть `.clasp.json`: зеркало ничего никуда не заливает и рабочей папкой
инструмента выкладки не является. Порядок выкладки — в CLAUDE.md, раздел «Деплой Bridge через
clasp»: база слияния собирается **под заход** в отдельном каталоге поверх свежего HEAD-пула,
и выкладывают оттуда.

## Как обновлять зеркало

После КАЖДОЙ выкладки (версия прода сменилась) — снять свежий отпечаток и переложить сюда
исходники прод-версии вместе с пересчитанным `MIRROR.json`, затем коммит с номером версии
в сообщении. Пока зеркало не обновлено, `bridge_prod_diff.py` честно кричит о расхождении —
это не ложная тревога, а напоминание.

## `MIRROR.json`

Паспорт снимка: номер прод-версии, script id, когда и чем снят, совпадал ли HEAD с продом,
и `sha256` каждого файла. Хеши сверяет тест `tests/test_bridge_prod_mirror.py` — молчаливая
правка файла зеркала (когда зеркало правят вместо прода) станет красным в гейте, а не сюрпризом
на выкладке.
